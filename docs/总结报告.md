# MossCode 实现与测试总结报告

更新日期：2026-08-31

## 1. 项目结论

MossCode 已形成可运行的 Web 图形化 coding agent：用户指定本地工作区并发送任务后，系统通过 Planner、Explorer、Coder、Reviewer 四个角色串行协作，调用 DeepSeek 的 OpenAI-compatible Chat Completions 与原生 tool calling，自主读取和写入文件、搜索代码、运行命令并在 GUI 中实时展示过程。模型客户端之外的任务编排、工具执行、上下文交接、循环终止和异常处理均由本项目实现，未使用 Agent 框架或云端文件执行工具。

## 3. 架构与模块分工

```text
React/Vite GUI
  ├─ i18n 中英文资源
  ├─ 对话时间线与折叠工具卡
  └─ 文件 / Diff / 终端检查器
              │ HTTP + SSE
FastAPI
  ├─ Session API 与内存事件流
  ├─ Orchestrator：四角色调度、handoff、停止条件
  ├─ LLM Client：DeepSeek 兼容请求与异常归一化
  └─ Tool Registry + Workspace：本地执行与安全边界
```

- Planner：只读理解任务，给出可验证计划。
- Explorer：只读检索仓库，为后续角色提供最小必要上下文。
- Coder：唯一拥有写入权限的角色，负责实现与定向验证。
- Reviewer：无写权限，独立读取改动并运行验证命令。
- Orchestrator：按固定状态机调度角色，仅传递精简自然语言 handoff，防止不同角色共享原始 tool call 后产生协议污染。

## 4. 本轮关键迭代

1. 修复发送体验：会话创建成功后立即清空输入框；创建失败时保留原输入供重试；刷新恢复历史会话时不把旧任务重新塞回输入框。
2. 修复空白页与连接问题：修正 React effect 返回值问题，并允许 `localhost:5173` 与 `127.0.0.1:5173` 跨域访问后端。
3. 修复“任务完成但无文件变化”：识别改动意图；Coder 未调用 `write_file` 时追加一次明确提醒，仍未写入则任务失败，不再假成功。
4. 修复上下文污染：角色不再继承上一个角色的原始 assistant/tool 消息，仅接收最近三条简短 handoff。
5. 优化对话可读性：完成的工具请求去重；工具名和结果摘要本地化；参数、JSON、命令输出与长回复默认折叠；API 错误码映射为自然中文或英文。
6. 修复内部状态泄露：轮次耗尽时不再显示 `agent_turn_limit_reached`，改为可读说明并保留工具记录。
7. 修复 Windows 解释器猜测：向可执行命令的角色提供后端实际 Python 路径，避免依次尝试 `python3`、`python`、`py`。
8. 优化响应式布局：桌面端固定三栏工作台并让消息、任务栏、检查器独立滚动；平板转为两栏；手机纵向排列，四个角色在 390px 宽度完整展示。
9. 完善国际化：固定 UI、角色目标、工具名、完成摘要和错误提示均从 `zh-CN.json` / `en-US.json` 读取；模型原始回复不强制翻译。
10. 重构右侧检查器：新增独立的递归工作区扫描接口；文件页按目录层级展开，自动忽略依赖和缓存目录；变更页以文件树选择逐文件 Diff；终端页按命令展示成功状态、退出码和输出。
11. 加入持久多轮记忆：新增 SQLite `sessions / turns / events` 数据模型、会话列表和追加轮次 API；GUI 可新建、选择并继续历史对话。修改当前路径后发送会自动新建对话，从而保持旧会话工作区一致且允许自由切换工作目录。
12. 加入长上下文管理：较早轮次压缩为持久摘要，保留最近三轮原始问答和当前任务；角色内部消息超过预算时按完整 assistant/tool 调用组裁剪，避免破坏 tool call 协议。
13. 封装内部协作事件：聊天区只显示用户输入、统一 Markdown 最终回复和错误；工具事件继续驱动文件、变更和终端检查器。
14. 加入运行中插话队列：补充消息按 FIFO 写入 SQLite，在当前四角色轮次结束后自动执行，并按轮次截断上下文，避免后续要求提前泄漏。
15. 加入用户可见的脱敏阶段反馈与秒级耗时统计；每轮仅显示主要阶段及首次写入/验证里程碑，不暴露角色原文、工具参数或 JSON。
16. 修复长时间不返回：本地工具转移到工作线程，后台进程启动命令直接拒绝；命令超时时终止其精确子进程树，避免阻塞 API、SSE 与最终总结。
17. 加入 Reviewer 质量门：Reviewer 必须输出结构化 PASS / NEEDS_WORK 结论；缺少结论或拒绝验收时任务不会假完成，且自然语言前缀和多次结论标记均能稳定解析。
18. 限制实现前的无效探查：Planner 不再重复调用文件工具，Coder 首次写入前最多进行 5 次列表、读取或搜索，避免在轮次耗尽前始终没有文件变化。
19. 加入刷新后的兜底轮询：运行中的任务刷新页面后会恢复忙碌状态和耗时统计；SSE 丢失时每 2 秒查询一次会话，完成后自动刷新事件、文件树和最终总结。
20. 修复命令进度误导：同一轮只展示最新一次写入/命令状态；首次失败后验证成功会明确显示“先前问题已修复”，不会让旧失败覆盖最终结果。
21. 修复 Reviewer 已验证却误失败：达到常规轮次上限后追加一次禁用工具的强制收尾，使 Reviewer 基于既有证据输出最终验收标记。
22. 修复会话切换竞态：会话加载、轮询和 SSE 均校验当前请求版本与会话 ID，已经发出的旧请求不能覆盖新会话。
23. 加入本机登录与权限审批：账号来自 `.env`，HttpOnly Cookie 保存短期会话；终端支持自动、逐条询问、完全禁用，询问模式通过实时事件暂停并等待单次授权。
24. 扩展主题与动效：保留 `style/prompt.xml` 不变，以集中 token 派生“米纸明亮 / 森林暮色”主题；增加有机背景漂移、消息入场、恢复状态、输入聚焦和触觉按钮动效，并支持减少动态效果偏好。

## 6. 安全与凭据

- `.env` 被 `.gitignore` 排除，仓库只保留无真实凭据的 `.env.example`。
- 所有文件路径经 `Path.resolve()` 后检查必须位于用户选择的工作区。
- 高风险命令关键字直接拦截；命令默认 30 秒超时，输出最多保留 12000 字符。
- 大文件、搜索结果数、读取行数和重复工具调用均有限制，避免无限循环与上下文膨胀。

## 7. 已知限制与提交前清单

当前已实现 SQLite、多轮追问、字符预算、旧轮摘要和重启恢复。现阶段使用字符数近似 token 数，不依赖厂商 tokenizer；旧轮摘要是确定性压缩，不是语义向量检索，因此不适合跨大量会话做知识库问答。高风险命令首版采用直接拒绝，尚未实现 GUI 审批；当前四角色串行执行，尚未实现 Reviewer 自动返工。这些属于后续增强，不影响持久多轮 coding agent 闭环。
