# NJUSE AgentProj 项目计划书

## 1. 项目定位

**项目名**：MossCode - 可视化多智能体编程助手
**目标**：独立实现一个中文图形化 coding agent。它能在受控工作区内读取、编辑代码，执行命令与测试，并以可追溯的多角色协作流程完成真实编程任务。

本项目不使用 LangChain、OpenAI Agents SDK、AutoGen、CrewAI 等 agent 框架。模型 API、原生 tool calling 可以使用；任务编排、工具定义与本地执行、上下文和会话管理、错误恢复、终止条件均由项目代码实现。

## 2. 目标用户与核心场景

| 场景 | 用户操作 | 系统结果 |
| --- | --- | --- |
| 新功能开发 | 输入需求并选择工作区 | 规划、定位相关文件、编码、执行测试、展示 Diff |
| 缺陷修复 | 粘贴报错或描述问题 | 分析日志、修改代码、验证修复 |
| 代码理解 | 询问某个模块的行为 | Explorer 只读检索后给出中文说明和引用文件 |
| 安全演示 | 触发写文件或命令 | GUI 展示动作、参数、风险等级与执行结果 |

## 3. 成功标准（MVP）

1. 用户可在中文 Web GUI 创建任务、选择本地工作区、查看完整执行时间线。
2. 系统有 Planner、Explorer、Coder、Reviewer 四个受限角色，由 Orchestrator 按状态机串行调度。
3. 至少实现文件列表、文件读取、受限文件写入、命令执行四种本地工具；工具结果须结构化记录。
4. 能完成一个真实的小型任务：理解现有仓库、修改 1-3 个源文件、运行测试、展示 Diff 与最终结论。
5. 因模型输出异常、工具失败、超时、连续无进展或超出轮数时，系统能停止并说明原因。

## 4. 总体架构

```text
React + TypeScript 中文 GUI
  ├─ 任务输入与会话页          ├─ 文件树 / Diff / 终端面板
  ├─ 智能体协作时间线          └─ 风险操作审批与运行配置
                         │ HTTP + SSE
FastAPI 后端
  ├─ Session API / SSE 推送
  ├─ Orchestrator 状态机
  ├─ Context Manager / LLM Client
  ├─ Tool Registry / Policy Guard
  └─ Workspace Runtime
                         │
受控本地工作区：文件系统、命令进程、测试输出
```

**技术选型**：前端 React + TypeScript + Vite；后端 Python + FastAPI；协议采用 OpenAI-compatible Chat Completions/tool calling，便于更换模型网关；SSE 用于实时事件流。首版不引入数据库，以 JSONL 运行日志和内存会话实现，后续可替换为 SQLite。

## 5. 模块与职责边界

| 模块 | 主要职责 | 输入 / 输出 | 不负责 |
| --- | --- | --- | --- |
| `frontend` | 中文界面、实时可视化、审批交互、Diff 展示 | SSE 事件 / 用户任务 | 决策、执行本地命令 |
| `api` | 创建会话、校验请求、SSE 流 | HTTP 请求 / 事件流 | 智能体推理策略 |
| `orchestrator` | 状态机、角色调度、重试和终止判断 | 会话状态 / 下一角色 | 直接读写文件 |
| `agents` | 角色提示词和可用工具白名单 | 上下文 / tool calls | 运行工具、跨角色直接通信 |
| `llm` | 兼容模型请求、tool call 解析、错误归一化 | messages + tools / 模型响应 | 上下文裁剪策略 |
| `context` | 消息裁剪、旧记录摘要、仓库概览 | 事件历史 / 有限上下文 | 文件执行 |
| `tools` | 参数校验、文件与命令的本地执行 | tool call / Observation | 调度哪个角色 |
| `runtime` | 工作区边界、路径解析、超时、输出截断 | 工具请求 / 原始结果 | LLM 调用 |
| `storage` | JSONL 事件与会话元数据 | 领域事件 / 可回放日志 | 实时推送 |

### 角色分工与权限

| 角色 | 职责 | 可用工具 | 退出条件 |
| --- | --- | --- | --- |
| Planner | 将用户请求拆成可验证步骤，输出计划 | `list_files`、`read_file` | 计划生成或只读失败 |
| Explorer | 查找相关代码并给 Coder 提供最小上下文 | `list_files`、`read_file`、`search_text` | 返回文件清单与摘要 |
| Coder | 实施修改、运行定向测试 | 全部工具 | 完成修改并给出验证命令 |
| Reviewer | 独立检查 Diff、运行测试、判定是否返工 | `list_files`、`read_file`、`run_command` | 通过，或给出一组可执行返工意见 |
| Orchestrator | 调度上述角色、限制返工轮数 | 不直接调用文件工具 | 通过、失败、取消、达到预算 |

角色仅经由结构化事件协作，禁止“无限互聊”。默认链路：`Planner → Explorer → Coder → Reviewer → 完成`；Reviewer 发现问题时仅允许 `Reviewer → Coder → Reviewer` 再执行一次。

## 6. Agent 内核设计

### 6.1 事件模型

所有步骤写入可回放事件：`task_created`、`agent_started`、`llm_requested`、`tool_requested`、`tool_finished`、`agent_finished`、`review_requested`、`task_finished`、`task_failed`。每条事件包含时间、会话 ID、角色、关联步骤、脱敏后的参数和摘要。

### 6.2 工具契约

| 工具 | 关键规则 |
| --- | --- |
| `list_files(path)` | 路径必须位于工作区；忽略 `.git`、依赖目录和二进制大文件 |
| `read_file(path, start, end)` | 文本、行数和字节数均限额；超限时分段返回 |
| `search_text(query, path)` | 限制结果数和单行长度，避免上下文膨胀 |
| `write_file(path, content)` | 仅限工作区；拒绝越界路径；返回修改前后摘要和 Diff |
| `run_command(command, cwd)` | cwd 仅限工作区；超时、中止、输出截断；首版对高风险命令要求 GUI 审批 |

### 6.3 终止与恢复

- 正常：Reviewer 通过，或模型显式给出最终回答且无待处理工具调用。
- 上限：默认每角色最多 6 次模型调用、全任务最多 18 轮、Reviewer 返工最多 1 轮。
- 失败：无效 tool call、连续两次相同失败、命令超时、模型请求失败达到重试上限。
- 恢复：将错误作为 Observation 回传当前角色；若失败可恢复则一次退避重试，否则由 Orchestrator 结束并在 GUI 提示人工接管。

## 7. GUI 与设计系统

界面中文化，遵循 `style/prompt.xml` 的 Organic / Natural 风格：米白纸张底色、苔藓绿主色、陶土橙强调、柔和不规则圆角、低强度纸张颗粒和自然阴影。视觉要温和，但终端输出和错误状态仍须清晰、可读。

### 7.1 主题可扩展策略

首版仅交付 `light`，但**所有颜色均通过语义 CSS 变量使用**，组件中禁止写业务色值。主题由 `data-theme="light"` 挂在根节点，未来新增主题只添加一个 token 文件，不改组件。

```text
frontend/src/styles/
  tokens.css          # token 名称、默认值与类型说明
  themes/light.css    # 唯一已实现主题
  base.css            # 字体、颗粒、可访问性与全局样式
  components.css      # 可复用组件样式
```

建议 token 分层：

```text
原始色：--palette-moss-600、--palette-clay-500、--palette-paper-50
语义色：--color-bg、--color-surface、--color-text、--color-primary
状态色：--color-success、--color-warning、--color-danger、--color-info
对象色：--agent-planner、--agent-explorer、--agent-coder、--agent-reviewer
```

对象色用于时间线区分角色，状态色用于成功、等待审批、失败等语义；两者不可混用。颜色之外，圆角、阴影、间距、字体也定义 token。

### 7.2 首版页面

1. **任务页**：任务输入、工作区、模型、运行按钮和安全模式。
2. **工作台**：左侧会话与文件树；中部多 agent 时间线；右侧文件内容 / Diff / 终端三标签页。
3. **审批弹窗**：准确显示命令或目标文件、风险说明、允许一次 / 拒绝。
4. **结果摘要**：计划、实际变更、测试结果、耗时、停止原因和可复制运行日志。

## 10. 风险与取舍

| 风险 | 对策 |
| --- | --- |
| 多 agent 导致延迟、成本、失控 | 串行状态机；角色白名单；严格总轮数和返工次数 |
| 模型生成危险命令 | 路径边界、命令超时、高风险审批、全量审计事件 |
| 上下文超限 | 目录概览 + 按需读取 + 输出截断 + 历史摘要 |
| GUI 工期膨胀 | 优先时间线、Diff、终端；动画与高级配置放到最后 |
| 演示不稳定 | 使用预先准备的小型本地样例仓库；固定模型与任务；保留事件回放 |

## 11. 答辩可阐释的设计决策

1. 使用状态机而非自由群聊：可预测、可限制成本、便于定位问题。
2. Coder 独占写权限：把分析与副作用分离，降低误改风险。
3. Reviewer 独立运行：将“生成代码”和“验证代码”解耦，形成最小闭环。
4. 工具结果结构化且可回放：既给模型反馈，也能在 GUI 与答辩中解释每一步。
5. 语义设计 token：保障 light 主题一致性，并让未来自定义主题只替换变量而非重写界面。
