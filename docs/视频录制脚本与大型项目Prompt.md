# MossCode 两分钟视频录制脚本与大型项目 Prompt

## 一、录制前准备

1. 新建一个空工作区，例如 `C:\Desktop\mosscode-video-demo`。
2. 启动 MossCode，选择 light 主题和中文界面。
3. 在设置中选择“四 Agent”，终端权限选择“每次执行前询问”，跨对话记忆保持开启。
4. 清理演示工作区，确认画面中不会出现 `.env`、API Key、个人通知或无关窗口。
5. 录制分辨率建议 1920×1080；模型等待部分可加速 2-4 倍，但保留一次命令授权和最终结果的正常速度。

## 二、可直接粘贴的大型项目 Prompt

```text
在当前空工作区从零实现一个可运行的中文全栈项目“松林任务台”，不要只给方案，必须实际创建文件并运行测试。

技术限制：
- 后端使用 Python FastAPI + SQLite，不使用 ORM；前端使用原生 HTML/CSS/JavaScript，不引入需要联网安装的前端框架。
- 数据库路径必须支持环境变量 SONGLIN_DB_PATH，默认使用工作区内 songlin.db。
- 不能启动常驻服务器进行测试；使用 FastAPI TestClient 和 tempfile 临时数据库完成可重复测试。
- API、页面和测试代码都要放在清晰的文件结构中；不得修改工作区外文件。

业务功能：
1. 任务包含 id、title、description、status、priority、due_date、created_at、updated_at。
2. status 仅允许 todo / doing / done，priority 仅允许 low / medium / high；非法值返回 422。
3. 实现创建、列表、详情、更新、删除接口；缺失任务返回 404。
4. 列表支持按 status、priority 和关键词筛选，支持按创建时间或截止日期排序。
5. 提供统计接口，返回总数、各状态数量和逾期未完成数量。
6. 中文单页界面要有新增表单、筛选器、统计卡片、任务列表、编辑、完成和删除操作；需要空状态、错误提示、加载状态和手机端适配。
7. 页面标题和页脚必须出现“松林任务台”，视觉简洁但完整，所有按钮具备明确中文文案和基本可访问性。

工程与验收：
- 至少创建 main.py、static/index.html、tests/test_app.py、requirements.txt、README.md。
- tests/test_app.py 必须使用 unittest + TestClient + tempfile，覆盖首页项目名、创建、读取、更新、删除、status/priority/关键词筛选、统计、422、404，并证明测试数据库位于临时目录。
- README 写清环境、安装、启动、测试命令、API 概览和项目结构。
- 完成后使用当前 Python 解释器运行完整测试；若失败，依据真实输出继续修复，直到退出码为 0。
- 最终只返回面向用户的简洁 Markdown 总结，列出修改文件、测试数量、执行命令和真实退出码；内部四角色讨论不要暴露。
```

| 0:12-0:25 | 打开设置模态框，依次点 Agent、记忆、规则、Hooks、MCP | “它支持单 Agent、四角色和自适应模式；设置采用工作区级规则与扩展，API Key 只在本机后端。” |
| 0:25-0:38 | 选择四 Agent、命令询问模式，粘贴 Prompt 并发送 | “这次演示从空目录构建一个真实的 FastAPI + SQLite 全栈项目。” |
| 0:38-0:50 | 显示计时、阶段进度；处理中再发送一句补充要求 | “执行在后台持久化，思考时仍可输入，补充消息会在当前轮结束后按顺序处理。” |

| 1:42-1:53 | 终端面板与检查点入口 | “工具结果可审计；每轮首次写入会建立独立检查点，恢复前还会检查人工改动冲突。” |
| 1:53-2:00 | 回到设置中的单/多 Agent 选项或架构图 | “实测简单任务单 Agent 更快，复杂任务才使用独立探索和复核；这是可解释的工程取舍。” |

## 四、录制时应避免

- 不展示 `.env`、请求头、API Key 或真实密钥配置页面的开发者工具。
- 不声称四 Agent 一定优于单 Agent；应说明它用额外开销换取独立复核。
- 不把模型自然语言总结当作测试证据，画面中要展示真实命令和退出码。
- 不在视频中花时间滚动内部 JSON；重点展示用户输入、阶段进度、最终答复、Diff 和终端证据。
