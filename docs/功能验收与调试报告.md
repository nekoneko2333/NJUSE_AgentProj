# MossCode 功能验收与调试报告

## 检查范围

本轮按作业要求、后端 Agent 核心、REST/SSE 状态、SQLite 持久化、工作区安全、文件工作台、设置与扩展、响应式界面和提交材料九个方面检查。自动测试不读取真实 API Key；性能基准单独使用本机配置的模型，并只操作 Git 忽略的临时工作区。

## 作业硬性要求覆盖

| 要求 | 状态 | 证据 |
| --- | --- | --- |
| 自主读写文件和执行命令 | 通过 | `ToolRegistry` 本地实现列表、读取、搜索、写入、命令工具 |
| 不使用现成 Agent 框架/SDK | 通过 | 依赖仅为 FastAPI、Uvicorn、HTTPX、dotenv；Agent 循环由项目实现 |

| 对话历史与上下文管理 | 通过 | SQLite 轮次、摘要窗口、最近上下文、可选跨对话记忆和最新偏好覆盖 |
| 模型输出解析 | 通过 | 原生 tool calls、参数 JSON、兼容文本格式和 Reviewer verdict 解析 |
| 循环终止条件 | 通过 | 角色轮次、重复调用保护、取消点、写入和验证证据门槛 |

| API Key 不入库 | 通过 | `.env` 被忽略；跟踪文件扫描未发现 `sk-...` 密钥 |

## 功能质量门

- 后端 `unittest`：38 项通过。
- 前端 Vitest：3 个文件、6 项测试；本轮修复文件编辑测试的异步交互超时问题。
- TypeScript `tsc --noEmit`：通过。
- Vite 生产构建：通过。
- Playwright：登录、会话恢复、Markdown、Diff、设置、1440×900 / 900×800 / 390×844 布局通过。
- 真实 DeepSeek：跨对话改名后，旧对话能够读取最新名称。
- Agent 模式基准：单 Agent 与四 Agent 各 3 次，均通过外部 6 项测试且未修改测试文件。

## 已发现并修复

1. 普通身份对话错误进入四角色 Reviewer：增加会话意图分流和统一助手身份。
2. 跨对话改名被旧会话偏好覆盖：同类名称偏好改为工作区最新声明优先。
3. 重试成功仍显示旧失败卡片：聊天只展示同一轮最新尝试。
4. 设置占用工作台且信息拥挤：改为背景虚化的单模态卡片，左侧分类、右侧详情。
5. 文件工作台测试偶发超过 5 秒：移除逐字符输入和隐式等待，改为确定性状态更新。

## 当前限制与提交风险

- 本地登录会话保存在后端内存，重启服务后需要重新登录；业务会话和执行记录不会丢失。
- MCP 首版仅支持本地 stdio，不支持远程 OAuth。
- 多 Agent 在简单任务上开销明显，不应作为所有任务默认最优解。
- 作业要求 Git 仓库公开；当前给出的 GitHub 仓库此前为私人仓库，需要在提交前由仓库所有者改为 Public。
- 作业要求 2 分钟以内、MP4、200 MB 内的视频；本仓库只提供录制 Prompt 与脚本，最终视频仍需实际录制。
